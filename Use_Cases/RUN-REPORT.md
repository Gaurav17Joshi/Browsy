research five open-weight models, read YouTube comments for public sentiment,
write the findings to disk, and build an interactive comparison page.

**It finished, the research was good, and the page came out broken.** The cause
is worth more than the numbers, so it has its own section.

## What broke: the page is a shell

The tab opened and looks plausible. Underneath, the content is missing:

| element | expected | actual |
|---|---|---|
| table rows | 5 | **1** (the header) |
| model cards | 5 | **0** |
| filter chips | yes | yes (5, static HTML) |
| sortable headers | yes | yes (static HTML) |
| benchmark bars | yes | 0 |
| logo tiles | yes | 0 |

Everything present is static markup. Everything absent was to be generated by
the page's own script, which is 12,405 characters, syntactically valid, and ends
with a `render()` call. Executing it by hand gives the reason:

```
TypeError: Failed to set the 'innerHTML' property on 'Element':
This document requires 'TrustedHTML' assignment.
```

**A `blob:` URL inherits the CSP of the page that created it.** The blob was
created on YouTube, YouTube enforces Trusted Types, and so the generated page
inherited a policy forbidding `innerHTML`. Every render call threw. The static
shell painted; nothing else did.

This is not the model's mistake. It followed the instructions given to it, and
the instructions were wrong — nothing in `prompt.txt` or `web-design.md`
mentions inherited CSP. The irony is that `cuaexp/panel.py` has carried a
Trusted Types workaround for months, for exactly this reason, on exactly this
site.

### Verified fix

Reproduced both routes with the same HTML, one that renders three rows and three
cards via `innerHTML`:

| route | rows | cards | panel visible |
|---|---|---|---|
| blob created on youtube.com | **0** | **0** | yes |
| `write_file` + `navigate("file://…")` | **3** | **3** | after ~2s |

A `file://` page inherits no CSP, so `innerHTML` works normally. The panel
disappears across the cross-origin navigation and the daemon's 2-second watchdog
puts it back, which is fine for recording but worth knowing about.

That route is better anyway: the page is a real file that outlives the session,
instead of a blob URL that dies with the tab that made it.

Two smaller options exist — create the blob from `about:blank` instead of from a
site, or have the generated page install its own Trusted Types policy — but
writing the file is simpler and produces something you keep.

## Changes worth making

1. **Switch the page from blob to `write_file` + `file://`.** The one change
   that turns this demo from broken to working.
2. **Say so in `web-design.md`**: a generated page inherits the CSP of wherever
   it was created; prefer building the DOM with `createElement`/`textContent`
   over `innerHTML` regardless, since that is immune to the whole class.
3. **Ask for the page to be checked after opening.** One `run_js` reading back
   `document.querySelectorAll('tbody tr').length` would have caught this in the
   run rather than afterwards.
4. The 120-turn cap was never close to binding at 56 calls. Leave it.

## Verdict

The agent did the hard part well — five models researched, eight YouTube pages
read, 27KB of sourced notes, the one genuinely interesting finding surfaced on
its own — and then fell at a fence nobody had told it was there. The failure was
in the brief, not the driving.

At $3.10 and nine minutes, re-running it after the fix is cheap.
